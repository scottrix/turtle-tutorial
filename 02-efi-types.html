2. UEFI Fundamentals & EFI Type Definitions

What is UEFI?

UEFI (Unified Extensible Firmware Interface) is the replacement for the legacy PC BIOS. When you power on a modern x86_64 machine, the UEFI firmware:

  1. Initializes hardware (RAM, PCI, USB, etc.)
  2. Sets up 64-bit long mode with identity-mapped memory
  3. Finds a FAT32 partition on a disk (the EFI System Partition)
  4. Looks for a file at \EFI\BOOT\BOOTX64.EFI
  5. Loads it as a PE+ executable and jumps to its entry point

That's it. Your code starts executing in 64-bit long mode, with a stack, with memory mapped 1:1 (virtual address = physical address), and with a set of boot services you can call to do things like allocate memory, find protocols (UEFI's word for device drivers), and draw to the screen.

The UEFI calling convention

UEFI uses the Microsoft x64 calling convention (also called __ms_abi in GCC). This is different from the System V AMD64 ABI used by Linux, macOS, and most Unix systems:

System V AMD64 (Linux)Microsoft x64 (UEFI)
1st argrdircx
2nd argrsirdx
3rd argrdxr8
4th argrcxr9
5th+ argsstackstack
Return valraxrax
Caller-savedrax,rcx,rdx,rsi,rdi,r8-r11rax,rcx,rdx,r8-r11
Callee-savedrbx,rbp,r12-r15rbx,rbp,rdi,rsi,r12-r15
Shadow spacenone32 bytes on stack

The critical difference: every function that UEFI calls, or that calls a UEFI function, must use the MS ABI. Rather than relying on the compiler-specific __attribute__((ms_abi)), we handle this with an assembly translation layer (efi_call.S) that provides efi_call0 through efi_call6 wrappers. These wrappers receive arguments in the SysV ABI convention and translate them to the MS ABI before calling the UEFI function. This approach is compiler-independent — it works with GCC, PCC, or any C compiler.

We cover the ABI translation layer in detail in Chapter 16. The key point for now: no C code in our project uses __attribute__((ms_abi)). All ABI translation happens in one assembly file.

Our own type definitions

Since we cannot include any standard headers (-nostdinc), we must define every type ourselves. Here is our include/kernel/types.h: 

#ifndef TURTLE_TYPES_H
#define TURTLE_TYPES_H

typedef unsigned char uint8_t;
typedef unsigned short uint16_t;
typedef unsigned int uint32_t;
typedef unsigned long uint64_t;

typedef signed char int8_t;
typedef signed short int16_t;
typedef signed int int32_t;
typedef signed long int64_t;

typedef unsigned long size_t;
typedef signed long ssize_t;
typedef signed long ptrdiff_t;
typedef unsigned long uintptr_t;
typedef signed long intptr_t;

#define NULL ((void *)0)

#ifndef TRUE
#define TRUE 1
#endif
#ifndef FALSE
#define FALSE 0
#endif

#define BIT(n) (1UL << (n))

#endif

Key point: on x86_64 Linux, unsigned long is 8 bytes. This is important because the UEFI spec defines UINTN as "native width unsigned integer", which is 8 bytes on 64-bit platforms.

EFI types

Now we define the UEFI types in include/boot/efi.h. The UEFI specification uses a set of integer types and handles: 

#define EFIAPI __attribute__((ms_abi))

typedef uint16_t CHAR16;
typedef uint8_t  UINT8;
typedef uint16_t UINT16;
typedef uint32_t UINT32;
typedef uint64_t UINT64;
typedef uint64_t UINTN;
typedef int32_t  INT32;
typedef int64_t  INT64;
typedef uint64_t EFI_STATUS;
typedef void    *EFI_HANDLE;
typedef void    *EFI_EVENT;
typedef uint64_t EFI_PHYSICAL_ADDRESS;

EFI_STATUS is the return type for every UEFI function. A value of 0 means success. Error codes have the high bit set (bit 63). This is checked with a macro: 

#define EFI_ERROR(status) (((INT64)(status)) < 0)
The INT64 cast is critical. If you cast to INT32 instead, then 0x8000000000000005ULL gets truncated to 0x00000005, which is positive, and EFI_ERROR() returns FALSE for every error code. We spent hours debugging this. Always use INT64.

EFI error codes

The UEFI spec defines error codes with the high bit set. We define the ones we need: 

#define EFI_SUCCESS             0
#define EFI_LOAD_ERROR          0x8000000000000001ULL
#define EFI_INVALID_PARAMETER   0x8000000000000002ULL
#define EFI_UNSUPPORTED         0x8000000000000003ULL
#define EFI_BAD_BUFFER_SIZE     0x8000000000000004ULL
#define EFI_BUFFER_TOO_SMALL    0x8000000000000005ULL
#define EFI_OUT_OF_RESOURCES    0x8000000000000009ULL
#define EFI_NOT_FOUND           0x800000000000000EULL
The ULL suffix is mandatory. Without it, 0x8000000000000005 may be interpreted as a 32-bit literal by the compiler, causing truncation. Always use ULL for EFI error codes.

EFI_GUID

UEFI identifies protocols and configuration tables using GUIDs (Globally Unique Identifiers), also known as UUIDs. The layout matches the EFI spec exactly: 

typedef struct {
    UINT32 Data1;
    UINT16 Data2;
    UINT16 Data3;
    UINT8  Data4[8];
} EFI_GUID;

GUIDs are specified as C struct initializers in our code. For example, the Graphics Output Protocol GUID: 

#define EFI_GRAPHICS_OUTPUT_PROTOCOL_GUID \
    { 0x9042a9de, 0x23dc, 0x4a38, \
      { 0x96, 0xfb, 0x7a, 0xde, 0xd0, 0x80, 0x51, 0x6a } }

EFI_MEMORY_DESCRIPTOR

The memory map returned by GetMemoryMap consists of an array of these descriptors: 

typedef struct {
    UINT32 Type;
    UINT32 Pad;
    UINT64 PhysicalStart;
    UINT64 VirtualStart;
    UINT64 NumberOfPages;
    UINT64 Attribute;
} EFI_MEMORY_DESCRIPTOR;

The Pad field aligns the struct to 8 bytes. Each descriptor describes a contiguous range of memory of a given type (conventional, reserved, MMIO, etc.).

EFI_SYSTEM_TABLE — the most important struct

This is the most important structure. UEFI passes a pointer to it as the second argument to our entry point. It contains pointers to console I/O, boot services, runtime services, and the configuration table array. 

typedef struct {
    EFI_TABLE_HEADER Hdr;
    CHAR16 *FirmwareVendor;
    UINT32  FirmwareRevision;
    UINT32  __pad0;                     /* alignment padding */
    EFI_HANDLE ConsoleInHandle;
    void      *ConIn;
    EFI_HANDLE ConsoleOutHandle;
    EFI_SIMPLE_TEXT_OUTPUT_PROTOCOL *ConOut;
    EFI_HANDLE StandardErrorHandle;
    EFI_SIMPLE_TEXT_OUTPUT_PROTOCOL *StdErr;
    void      *RuntimeServices;
    EFI_BOOT_SERVICES *BootServices;
    UINTN     NumberOfTableEntries;
    EFI_CONFIGURATION_TABLE *ConfigurationTable;
} EFI_SYSTEM_TABLE;
The struct layout must match UEFI exactly. We originally omitted five fields (ConsoleInHandle, ConIn, ConsoleOutHandle, StdErr, StandardErrorHandle) and had the wrong padding. This pushed BootServices from offset 96 to offset 48 — meaning our g_BS pointer was reading garbage. This bug took days to find. The UEFI spec lists every field; count the offsets yourself.

EFI_BOOT_SERVICES

This is the table of function pointers we use during the boot phase. It contains ~40 functions. We declare each function pointer type separately for type safety, then fill in the struct in order. For functions we don't call, we use void * as a placeholder: 

typedef struct {
    EFI_TABLE_HEADER Hdr;
    void *RaiseTPL;
    void *RestoreTPL;
    efi_allocate_pages     *AllocatePages;
    efi_free_pages         *FreePages;
    efi_get_memory_map     *GetMemoryMap;
    efi_allocate_pool      *AllocatePool;
    efi_free_pool          *FreePool;
    void *CreateEvent;
    void *SetTimer;
    /* ... many more ... */
    efi_exit_boot_services *ExitBootServices;
    /* ... */
    efi_open_protocol      *OpenProtocol;
    /* ... */
    efi_locate_protocol    *LocateProtocol;
    /* ... remaining fields ... */
} EFI_BOOT_SERVICES;

We use void * for every function pointer in every EFI struct. We don't need typed function pointers because we never call them directly — we always pass them through the assembly efi_callN() wrappers (see Chapter 16). This eliminates the need for __attribute__((ms_abi)) annotations entirely, making our code compilable with PCC.

Verifying struct offsets

A single wrong offset will crash your boot. After writing efi.h, verify the critical offsets: 

/* Quick test program (compile with host gcc, not freestanding) */
#include <stdio.h>
#include "include/boot/efi.h"

int main(void) {
    printf("sizeof(EFI_SYSTEM_TABLE) = %zu\n", sizeof(EFI_SYSTEM_TABLE));
    printf("BootServices offset      = %zu\n",
           (size_t)&((EFI_SYSTEM_TABLE *)0)->BootServices);
    printf("ConOut offset            = %zu\n",
           (size_t)&((EFI_SYSTEM_TABLE *)0)->ConOut);

    printf("sizeof(EFI_BOOT_SERVICES) = %zu\n", sizeof(EFI_BOOT_SERVICES));
    printf("GetMemoryMap offset       = %zu\n",
           (size_t)&((EFI_BOOT_SERVICES *)0)->GetMemoryMap);
    printf("ExitBootServices offset   = %zu\n",
           (size_t)&((EFI_BOOT_SERVICES *)0)->ExitBootServices);
    printf("OpenProtocol offset       = %zu\n",
           (size_t)&((EFI_BOOT_SERVICES *)0)->OpenProtocol);
    printf("LocateProtocol offset     = %zu\n",
           (size_t)&((EFI_BOOT_SERVICES *)0)->LocateProtocol);
    return 0;
}

Expected output (verified against the UEFI spec): 

sizeof(EFI_SYSTEM_TABLE)  = 104
BootServices offset       = 96
ConOut offset             = 56
sizeof(EFI_BOOT_SERVICES) = 280
GetMemoryMap offset       = 56
ExitBootServices offset   = 232
OpenProtocol offset       = 280
LocateProtocol offset     = 312

If your offsets don't match, you have a missing field, wrong padding, or a wrong type size. Do not proceed until they match.
