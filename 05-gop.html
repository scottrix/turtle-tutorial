5. The Graphics Output Protocol

Before we exit boot services, we need the framebuffer address. UEFI provides this through the Graphics Output Protocol (GOP). GOP tells us the resolution, pixel format, and the physical address of the linear framebuffer.

Getting the GOP interface

To find the framebuffer we use the canonical EDK2 pattern: enumerate handles supporting the GOP GUID with LocateHandle, then open the protocol interface on the first handle with OpenProtocol. This works for any protocol, not just GOP, and handles firmware that exposes multiple GOP instances (one per display). Every boot-services call goes through an efi_callN() wrapper from efi_call.S (see Chapter 16) that translates System V ABI arguments into the Microsoft x64 ABI the firmware expects. 

static EFI_STATUS get_gop(EFI_HANDLE ImageHandle,
                           EFI_GRAPHICS_OUTPUT_PROTOCOL **gop_out)
{
    EFI_GUID gop_guid = EFI_GRAPHICS_OUTPUT_PROTOCOL_GUID;
    UINTN buf_sz = sizeof(EFI_HANDLE) * 16;
    EFI_HANDLE handles[16];
    EFI_STATUS status;

    status = efi_call5(g_BS->LocateHandle, (void *)2, &gop_guid, NULL, &buf_sz, handles);
    if (EFI_ERROR(status))
        return status;

    UINTN num = buf_sz / sizeof(EFI_HANDLE);
    for (UINTN h = 0; h < num; h++) {
        void *iface = NULL;
        status = efi_call6(g_BS->OpenProtocol, handles[h], &gop_guid,
                                &iface, ImageHandle, NULL,
                                (void *)EFI_OPEN_PROTOCOL_GET_PROTOCOL);
        if (!EFI_ERROR(status) && iface) {
            *gop_out = (EFI_GRAPHICS_OUTPUT_PROTOCOL *)iface;
            return EFI_SUCCESS;
        }
    }
    return EFI_NOT_FOUND;
}

Let's break this down:

  • LocateHandle(2, ...) — the 2 is ByProtocol, meaning "find all handles that support this GUID". The function fills handles[] and sets buf_sz to the actual size written.
  • OpenProtocol — asks the firmware to give us the protocol interface for a specific handle. We pass ImageHandle as the AgentHandle (required by the spec) and EFI_OPEN_PROTOCOL_GET_PROTOCOL as the attribute (read-only access).
  • We try each handle until one succeeds. In practice there's usually just one GOP handle.

Reading the framebuffer info

Once we have the GOP interface, we read the mode information: 

if (!EFI_ERROR(status) && gop) {
    fb_info.base_addr = gop->Mode->FrameBufferBase;
    fb_info.size      = gop->Mode->FrameBufferSize;
    fb_info.width     = gop->Mode->Info->HorizontalResolution;
    fb_info.height    = gop->Mode->Info->VerticalResolution;
    fb_info.pitch     = gop->Mode->Info->PixelsPerScanLine * 4;
    fb_info.bpp       = 32;

gop->Mode points to the current mode structure, which contains the framebuffer base address (a physical memory address we can write pixels to), its size, and a pointer to the mode info.

pitch is the number of bytes per scanline. UEFI gives us PixelsPerScanLine, and since each pixel is 32 bits (4 bytes), we multiply by 4. The pitch may be larger than width * 4 if the hardware has padding at the end of each line.

Pixel formats

UEFI defines two main pixel formats:

  • PixelRedGreenBlueReserved8BitPerColor — byte order is R, G, B, reserved. The first byte at a pixel address is red.
  • PixelBlueGreenRedReserved8BitPerColor — byte order is B, G, R, reserved. The first byte is blue. This is the most common format on x86 hardware.

We detect the format and set the color shift values accordingly: 

if (gop->Mode->Info->PixelFormat ==
    PixelBlueGreenRedReserved8BitPerColor) {
    fb_info.red_shift   = 16;
    fb_info.green_shift = 8;
    fb_info.blue_shift  = 0;
} else {
    fb_info.red_shift   = 0;
    fb_info.green_shift = 8;
    fb_info.blue_shift  = 16;
}

These shift values are used later by the framebuffer driver to compose pixel colors. A pixel value of 0x00RRGGBB (or 0x00BBGGRR depending on format) is written directly to the framebuffer memory.

Why this matters after ExitBootServices

After we exit boot services, GOP is gone. We can't call QueryMode or SetMode. But the framebuffer memory is still there — it's a region of physical memory that the GPU reads from to display pixels. As long as we know the base address, resolution, and pitch, we can write pixels directly. That's exactly what our framebuffer console driver does (Chapter 9).
