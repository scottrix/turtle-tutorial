6. Memory Map & ExitBootServices

The final step before we can take over the machine is to read the memory map and exit boot services. This is the trickiest part of the entire boot process because of a subtle requirement: the memory map must be fresh at the moment we call ExitBootServices.

Getting the memory map

GetMemoryMap returns an array of EFI_MEMORY_DESCRIPTOR structures. The first call is a probe: we pass NULL for the buffer and the firmware tells us how big the buffer needs to be: 

EFI_MEMORY_DESCRIPTOR *memory_map = NULL;
UINTN map_size = 0, map_key = 0, desc_size = 0;
UINT32 desc_ver = 0;

status = g_BS->GetMemoryMap(&map_size, memory_map, &map_key,
                              &desc_size, &desc_ver);
if (status == EFI_BUFFER_TOO_SMALL ||
    status == EFI_INVALID_PARAMETER) {
    map_size += 4096 * 8;
    status = g_BS->AllocatePool(EfiLoaderData, map_size,
                                  (void **)&memory_map);
    if (EFI_ERROR(status))
        return status;
    status = g_BS->GetMemoryMap(&map_size, memory_map, &map_key,
                                  &desc_size, &desc_ver);
}

We add extra space (4096 * 8) because the map may grow between the probe and the real call. We allocate with AllocatePool (a boot service) and then call GetMemoryMap again with the real buffer.

GetMemoryMap returns EFI_BUFFER_TOO_SMALL on the first call (with map_size=0), but some implementations return EFI_INVALID_PARAMETER instead. We check for both.

Computing total conventional memory

uint64_t total_mem = 0;
UINTN entries = map_size / desc_size;
for (UINTN i = 0; i < entries; i++) {
    EFI_MEMORY_DESCRIPTOR *desc =
        (EFI_MEMORY_DESCRIPTOR *)((UINT8 *)memory_map + i * desc_size);
    if (desc->Type == EfiConventionalMemory ||
        desc->Type == EfiLoaderCode ||
        desc->Type == EfiBootServicesCode ||
        desc->Type == EfiBootServicesData) {
        total_mem += desc->NumberOfPages * 4096;
    }
}

Key detail: descriptors are not necessarily sizeof(EFI_MEMORY_DESCRIPTOR) apart. The desc_size value returned by GetMemoryMap may be larger (future versions of the spec may add fields). We always use desc_size to step through the array.

The map-key trap

This is the single most important thing to understand about ExitBootServices:

Any boot service call between GetMemoryMap and ExitBootServices invalidates the map key. If you call ExitBootServices with a stale key, it returns EFI_INVALID_PARAMETER and you cannot exit boot services.

This means you cannot:

  • Call print() (which calls ConOut->OutputString) between GetMemoryMap and EBS
  • Call AllocatePool between GetMemoryMap and EBS
  • Call any boot service function between them

Our solution: allocate a fresh buffer before the final GetMemoryMap, call GetMemoryMap, then immediately call ExitBootServices with no intervening boot service calls: 

UINTN ebs_map_size = 4096 * 64;
UINTN ebs_map_key = 0;
EFI_MEMORY_DESCRIPTOR *ebs_mmap = NULL;

status = g_BS->AllocatePool(EfiLoaderData, ebs_map_size,
                              (void **)&ebs_mmap);
if (EFI_ERROR(status)) return status;

/* This is the LAST GetMemoryMap before EBS. No boot service
   calls are allowed between this and ExitBootServices. */
status = g_BS->GetMemoryMap(&ebs_map_size, ebs_mmap,
                              &ebs_map_key, &ebs_desc_size,
                              &ebs_desc_ver);
if (EFI_ERROR(status)) return status;

status = g_BS->ExitBootServices(ImageHandle, ebs_map_key);
if (EFI_ERROR(status)) return status;

We use a separate buffer (ebs_mmap) so we can keep the original memory_map for the kernel's own use (passing it in boot_info).

What happens after ExitBootServices

Once ExitBootServices returns EFI_SUCCESS:

  • Interrupts are still enabled — we must disable them ourselves with cli
  • Boot services are gone — any call to g_BS will crash
  • The UEFI console is gone — we must use our own output (serial port or framebuffer)
  • Memory allocations are frozen — we own whatever we allocated; the firmware won't free or reclaim it
  • IDTR still points to UEFI's IDT — if an interrupt fires, it will jump to firmware code that may not be there anymore. This is why we cli immediately.
__asm__ volatile("cli");

From this point on, we are in bare-metal mode. The next steps are to set up our own GDT (Chapter 7) and start the kernel (Chapter 8).

Finding the RSDP

Before we exit boot services, we also look for the ACPI RSDP (Root System Description Pointer). This is needed later for hardware enumeration (finding PCI devices, HPET, APIC, etc.). We search the UEFI configuration table for the ACPI 2.0 GUID: 

uint64_t rsdp = 0;
EFI_GUID acpi_20_guid = ACPI_20_TABLE_GUID;
for (UINTN i = 0; i < g_ST->NumberOfTableEntries; i++) {
    if (guid_match(&g_ST->ConfigurationTable[i].VendorGuid,
                   &acpi_20_guid)) {
        rsdp = (uint64_t)g_ST->ConfigurationTable[i].VendorTable;
        break;
    }
}

We store this in boot_info.rsdp_addr for future use.
