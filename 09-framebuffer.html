9. The Framebuffer Console

Now we have a raw framebuffer — a big block of memory where each 4-byte value is a pixel color. We need to render text onto it. This means we need a font, a way to draw characters, and line-wrapping and scrolling logic. We also implement printk for formatted output.

The PC screen font

We use the classic 8×16 PC screen font: 256 characters, each defined as 16 bytes (one byte per scanline, 8 bits per pixel). The font is stored as a raw binary file (font.bin, 4096 bytes) and embedded into the kernel as a linkable object file.

To embed the binary file, we use objcopy to convert it to an ELF object: 

objcopy -I binary -O elf64-x86-64 -B i386 \
    --rename-section .data=.rodata,alloc,load,readonly,data,contents \
    src/drivers/font.bin build/drivers/font.o

This creates symbols we can reference from C: 

extern uint8_t _binary_src_drivers_font_bin_start[];
extern uint8_t _binary_src_drivers_font_bin_end[];

The symbol names are generated by objcopy from the file path, with dots and slashes replaced by underscores. The _start symbol points to the beginning of the font data, and _end marks the end.

Drawing a pixel

static void fb_draw_pixel(uint32_t x, uint32_t y, uint32_t color)
{
    if (x >= fb_info.width || y >= fb_info.height)
        return;
    uint32_t *pixel = fb_buffer + (y * (fb_info.pitch / 4)) + x;
    *pixel = color;
}

fb_buffer is a uint32_t * pointing to the framebuffer base address. We compute the offset as y * (pitch / 4) + x — dividing pitch by 4 because we're indexing uint32_t values, not bytes. Each 32-bit value is one pixel: 0x00RRGGBB or 0x00BBGGRR depending on the pixel format (detected in Chapter 5).

Drawing a character

static void fb_draw_char(char c, uint32_t x, uint32_t y)
{
    uint8_t *glyph = font_data + (uint8_t)c * FONT_HEIGHT;
    uint32_t px, py;
    for (py = 0; py < FONT_HEIGHT; py++) {
        uint8_t row = glyph[py];
        for (px = 0; px < FONT_WIDTH; px++) {
            if (row & (0x80 >> px))
                fb_draw_pixel(x + px, y + py, fb_fg);
            else
                fb_draw_pixel(x + px, y + py, fb_bg);
            }
    }
}

For each character, we look up its glyph in the font data. The glyph for character c starts at font_data + c * 16 (16 bytes per character). Each byte is one scanline: bit 7 is the leftmost pixel, bit 0 is the rightmost. We test each bit and draw either the foreground or background color.

Scrolling

When we reach the bottom of the screen, we scroll up by one line (16 pixels). We copy every pixel row up by 16 positions, then clear the bottom 16 rows: 

static void fb_scroll(void)
{
    uint32_t lines = FONT_HEIGHT;
    uint32_t pitch_dwords = fb_info.pitch / 4;

    for (y = 0; y < fb_info.height - lines; y++) {
        for (x = 0; x < fb_info.width; x++) {
            fb_buffer[y * pitch_dwords + x] =
                fb_buffer[(y + lines) * pitch_dwords + x];
        }
    }

    for (y = fb_info.height - lines; y < fb_info.height; y++) {
        for (x = 0; x < fb_info.width; x++) {
            fb_buffer[y * pitch_dwords + x] = fb_bg;
        }
    }
}

This is not fast (we're copying pixel by pixel instead of using memcpy), but it's correct and simple. For a production kernel, you'd use memcpy or even SIMD instructions for the bulk copy.

fb_putc: the core character output function

void fb_putc(char c)
{
    if (c == '\n') {
        fb_x = 0;
        fb_y += FONT_HEIGHT;
        if (fb_y + FONT_HEIGHT >= fb_info.height) {
            fb_scroll();
            fb_y -= FONT_HEIGHT;
        }
        return;
    }
    if (c == '\r') { fb_x = 0; return; }
    if (c == '\t') {
        fb_x = (fb_x + FONT_WIDTH * 4) & ~(FONT_WIDTH * 4 - 1);
        /* handle wrapping ... */
        return;
    }
    if (c == '\b') {
        if (fb_x >= FONT_WIDTH)
            fb_x -= FONT_WIDTH;
        return;
    }

    fb_draw_char(c, fb_x, fb_y);
    fb_x += FONT_WIDTH;
    if (fb_x + FONT_WIDTH >= fb_info.width) {
        fb_x = 0;
        fb_y += FONT_HEIGHT;
        if (fb_y + FONT_HEIGHT >= fb_info.height) {
            fb_scroll();
            fb_y -= FONT_HEIGHT;
        }
    }
}

This handles the basic control characters:

  • \n — move to next line (also scrolls if at bottom)
  • \r — return cursor to left edge
  • \t — advance to next tab stop (every 4 characters)
  • \b — backspace (move cursor left by one character)

For any other character, we draw it and advance the cursor. If we reach the right edge, we wrap to the next line (scrolling if needed).

printk: formatted output

We implement a minimal printf-like function using GCC's built-in variadic argument support: 

typedef __builtin_va_list va_list;
#define va_start(v, l) __builtin_va_start(v, l)
#define va_end(v)      __builtin_va_end(v)
#define va_arg(v, t)   __builtin_va_arg(v, t)

int printk(const char *fmt, ...)
{
    va_list ap;
    va_start(ap, fmt);

    while (*fmt) {
        if (*fmt != '%') {
            fb_putc(*fmt++);
            continue;
        }
        fmt++;
        /* handle %d, %u, %x, %X, %p, %c, %s, %l, %ll */
        /* ... (see source) ... */
    }

    va_end(ap);
    return count;
}

We support these format specifiers:

SpecifierTypeOutput
%d, %iint/long/long longSigned decimal
%uint/long/long longUnsigned decimal
%xint/long/long longLowercase hex
%Xint/long/long longUppercase hex
%ppointerHex with 0x prefix
%cintCharacter
%schar *String
%%—Literal %

The l and ll prefixes adjust the argument size: %ld = long, %lld = long long. This is a subset of the standard C printf, but it covers everything we need for kernel diagnostics.

String utilities

Since we're freestanding, we provide our own string functions in string.c: 

void *memset(void *s, int c, size_t n);

These are straightforward byte-by-byte implementations. In a production kernel you'd use architecture-specific optimizations (rep stosq, SSE, etc.), but correctness first.
