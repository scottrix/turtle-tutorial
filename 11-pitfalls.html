11. Lessons Learned & Pitfalls

Every OS developer hits a long tail of obscure bugs. This chapter documents every hard-won discovery we made, so you can avoid the same pain.

1. EFI_SYSTEM_TABLE offset bug

Symptom: g_BS pointed to garbage. Every boot service call crashed or returned nonsense.

Cause: Our EFI_SYSTEM_TABLE struct was missing five fields: ConsoleInHandle, ConIn, ConsoleOutHandle, StandardErrorHandle, and StdErr. Five missing 8-byte fields = 40 bytes. This shifted BootServices from offset 96 to offset 48.

Fix: Read the UEFI spec carefully and add every field. Verify offsets with a test program (see Chapter 2).

2. EFI error codes: the missing high bit

Symptom: Comparisons like status == EFI_BUFFER_TOO_SMALL never matched, even when the firmware returned that error.

Cause: We defined EFI_BUFFER_TOO_SMALL = 5. But UEFI returns 0x8000000000000005. The high bit (bit 63) is set for all error codes.

Fix: Define error codes with the ULL suffix and the high bit: 

#define EFI_BUFFER_TOO_SMALL 0x8000000000000005ULL

3. EFI_ERROR macro: INT32 truncation

Symptom: EFI_ERROR(status) always returned FALSE, even for error statuses.

Cause: We had #define EFI_ERROR(s) (((INT32)(s)) < 0). Casting 0x8000000000000005 to INT32 truncates to 0x00000005, which is positive. The sign bit we were checking is in bit 63, not bit 31.

Fix: Cast to INT64: 

#define EFI_ERROR(status) (((INT64)(status)) < 0)

4. LocateProtocol returns INVALID_PARAMETER

Symptom: LocateProtocol fails for every GUID, not just GOP.

Cause: Unknown. Possibly an OVMF bug or interaction with the gnu-efi relocator. We verified the calling convention and GUID bytes in disassembly.

Fix: Use LocateHandle + OpenProtocol instead (see Chapter 5). This two-step approach works perfectly.

5. Serial MMIO after ExitBootServices

Symptom: Writing to 0x3F8 as a memory address causes a page fault after EBS.

Cause: 0x3F8 as a memory address is not the serial port. It's just an address in low memory that UEFI's page tables may or may not map. The serial port is at I/O port 0x3F8, accessed via in/out instructions, not memory reads/writes.

Fix: Use outb with the I/O port: 

__asm__ volatile("outb %0, %1" : : "a"(c), "Nd"(0x3F8));

6. GDT granularity: wrong L/D bits

Symptom: Triple fault on lretq after loading the GDT.

Cause: We used granularity byte 0xA for the code descriptor. This has L=0, D=1 — meaning "32-bit code segment". But we're in 64-bit long mode. The CPU tried to enter 32-bit compatibility mode and faulted.

Fix: For 64-bit code, the granularity byte must be 0xAF (G=1, D=0, L=1, limit=0xF). For data segments in long mode, use 0xCF (G=1, D/B=1, L=0, limit=0xF).

7. ExitBootServices map-key invalidation

Symptom: ExitBootServices returns EFI_INVALID_PARAMETER.

Cause: We called print() (which calls ConOut->OutputString) between GetMemoryMap and ExitBootServices. This boot service call changed the memory map, invalidating the key.

Fix: No boot service calls between the final GetMemoryMap and ExitBootServices. Allocate the buffer before GetMemoryMap, call GetMemoryMap, then immediately call ExitBootServices.

8. entry.c compiled with wrong flags

Symptom: Linker errors about R_X86_64_64 relocations and DT_TEXTREL.

Cause: The Makefile's pattern rule matched entry.c with KERNEL_CFLAGS (-fno-pic -mcmodel=large), producing absolute relocations. EFI code must be compiled with -fpic -shared.

Fix: Add explicit rules for build/boot/entry.o and build/boot/efi_main.o that use EFI_CFLAGS.

9. QEMU OVMF on older versions

Symptom: QEMU immediately crashes or OVMF fails to initialize.

Cause: OVMF's 4MB pflash images require QEMU 8.0+. Older QEMU versions had bugs with the pflash driver.

Fix: Use QEMU 8.0 or later. On Arch Linux, sudo pacman -S qemu-system-x86 gives you a current version.

10. UART THR-empty bit in QEMU

Symptom: Serial output hangs when polling the Line Status Register (inb(0x3FD) & 0x20).

Cause: QEMU's emulated 16550 UART doesn't set the THR-empty bit in a timely manner. Polling loops spin forever.

Fix: Use a delay loop between characters instead of polling. Not ideal for production, but works for development.

The common thread in most of these bugs: the UEFI firmware is an unforgiving environment. There's no printf, no debugger (you can attach GDB to QEMU, but it's tricky with UEFI), and a wrong offset or calling convention crashes silently. Build incrementally, test after every change, and always have serial output as a debug channel.
